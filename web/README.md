# Lineup Builder — Web Version

A web-based variant of the **Lineup Builder** desktop application. This is a vanilla JavaScript (no framework) single-page application that mirrors the functionality of the desktop app while integrating with a remote REST API backend for club management, DJ bookings, Discord integration, and VRChat streaming.

## Overview

Lineup Builder Web enables DJs and club organizers to:
- **Create and manage event lineups** — add/remove/reorder time slots, assign DJs, set durations
- **Manage DJ rosters** — maintain a library of DJs with stream links, genres, and metadata
- **Browse and filter by genre** — tag slots with genres for flexible event organization
- **Generate formatted output** — export lineups as Discord-markdown or plain text with computed timings
- **Save/load events** — persist event configurations locally (browser storage) or to remote API
- **Authentication & cloud sync** — Discord OAuth login, cloud backup, image storage
- **VRChat & Discord integration** — fetch guild/channel info, manage bookings, post lineups to Discord

### Subdirectory Descriptions

#### `/src/models/`
Pure data structures and event bus. **No DOM or API calls here.**

- **`event-bus.js`** — Simple pub/sub: `subscribe(event, fn)`, `publish(event, data)`, `unsubscribe()`. All inter-module communication flows through the bus.
- **`lineup-model.js`** — Mutable state model mirroring `desktop/src/backend/models/lineup_model.py`:
  - `LineupModel` — holds title, vol, timestamp, slots, DJ library, genres, output format
  - `SlotData` — { name, genre, duration }
  - `DJInfo` — { name, stream, exactLink }
  - `EventSnapshot` — frozen snapshot for generating output; includes computed properties like `startDatetime`, `fullTitle`
  - Every mutation publishes `"model_changed"` on the bus

#### `/src/services/`
External I/O: API calls, storage, cloud sync. **Thread-safe for async operations.**

- **`api-client.js`** — REST wrapper:
  - `get(path)`, `post(path, body)`, `put(path, body)`
  - Configurable base URL via `VITE_API_URL` env var (default: same origin)
  - Error handling with descriptive messages
  - Proxied to `http://127.0.0.1:8000` during development

- **`storage.js`** — Browser LocalStorage wrapper:
  - `load()`, `save(key, value)`, `get(key)`, `delete(key)`, `clear()`
  - Persists: event lineups, DJ library, genres, settings, window state, theme
  - Auto-recovery on app start

- **`cloud-sync.js`** — High-level sync orchestration:
  - `backup(eventId)` — push lineup to server
  - `restore(eventId)` — pull lineup from server
  - Handles conflict resolution and retry logic

- **`image-storage.js`** — Image upload to S3-compatible endpoint:
  - `uploadImage(file)` — multipart form upload
  - Returns presigned URL for display

#### `/src/output/`
Pure string generation. **Stateless, no side effects.**

- **`output-generator.js`** — Mirrors `desktop/src/backend/output/output_generator.py`:
  - `generate(snapshot)` — returns formatted output (Discord markdown or plain text)
  - `computeSlotTimes(snapshot)` — array of "HH:MM" strings for UI labels
  - `vrcdnConvert(link, format)` — convert VRCDN stream links between "quest" and "pc" formats
  - Pure functions; safe to call from any context

- **`import-parser.js`** — Parse event text:
  - Extracts event title, timestamp, slots, DJ names from Discord markdown or plain text
  - Opens modal dialog for user to review/confirm imports
  - Triggers callback with parsed `EventSnapshot`

#### `/src/ui/`
All DOM manipulation and user interactions. **20+ manager classes, one per feature.**

- **Theme & Layout:**
  - `theme-manager.js` — Apply color presets (8 built-in + user-defined)
  - `tab-manager.js` — Switch left/right panel tabs (Event, Roster, DJ, Club)
  - `resize-manager.js` — Pan resize handle logic

- **Feature Managers (left panel):**
  - `events-manager.js` — Save/load/delete/duplicate named lineups (YAML-like JSON in localStorage)
  - `slot-manager.js` — Render slot rows: drag handle, time label, duration dropdown, DJ input, genre input, delete button
  - `roster-manager.js` — DJ roster sidebar; drag-to-slot payloads
  - `genre-manager.js` — Genre tag management (add/delete/toggle/filter)
  - `output-manager.js` — Output preview panel; format selection

- **Remote Integration:**
  - `auth-manager.js` — Discord OAuth flow; login pill in topbar
  - `discord-manager.js` — Fetch guilds/channels; compose & post lineups
  - `dj-manager.js` — Edit DJ records (name, genres, stream link, image); upload avatars
  - `club-manager.js` — Select active club; view bookings
  - `drag-drop-manager.js` — Drag DJ card → slot; highlight drop targets

- **UX:**
  - `settings-manager.js` — Theme selection, preset saving, theme reset
  - `modal-manager.js` — Central handler for all popups (confirm dialogs, DJ edit modal, etc.)
  - `toast.js` — Lightweight notification helper (success, error, info messages)

#### `/src/styles/`
CSS organized by concern. **CSS variables for theming.**

- **`reset.css`** — Remove browser defaults (margins, padding, list styles)
- **`theme.css`** — 50+ CSS variables:
  - Colors: `--color-primary`, `--color-panel-bg`, `--color-text-primary`, etc.
  - Spacing: `--space-1` (4px) through `--space-6` (24px)
  - Typography: `--text-xs` through `--text-xl`

- **`layout.css`** — Flexbox grid for topbar, left/right panels, tabs, split view
- **`components.css`** — Reusable styles for buttons, inputs, cards, modals, badges, tabs

## Architecture & State Flow

### Event-Driven Reactive Pattern

```
User input (e.g., change slot DJ name)
  ↓
UI Manager callback
  ↓
LineupModel.setSlotName(id, name)
  ↓
Model state mutates
  ↓
bus.publish('model_changed', {})
  ↓
Output Manager subscribes → OutputManager.update()
  ↓
OutputGenerator.generate(snapshot) → formatted string
  ↓
DOM update: display preview
```

### Core Components

| Component | Responsibility | Imports |
|-----------|---|---------|
| **App** (main.js) | Wire up all services & managers; top-level init | All |
| **EventBus** | Pub/sub for `model_changed`, `theme_changed`, `ui_updated` | (none) |
| **LineupModel** | Mutable state; publishes events on mutation | EventBus |
| **StorageManager** | Persist to localStorage | (none) |
| **ApiClient** | REST wrapper | (none) |
| **CloudSync** | Cloud backup/restore orchestration | ApiClient, StorageManager |
| **OutputGenerator** | Pure string generation (Discord/plain-text) | (none) |
| **Managers (UI)** | Render DOM, bind events, listen to bus | LineupModel, EventBus, StorageManager, etc. |

### Data Flow Example: Creating a New DJ

1. User clicks "Add DJ" in roster
2. RosterManager opens modal (via ModalManager)
3. User fills form; clicks "Save"
4. RosterManager calls `model.addDJ(name, stream, genres)`
5. LineupModel mutates internal state
6. LineupModel publishes `'model_changed'` on EventBus
7. OutputManager (subscribed to `'model_changed'`) wakes up
8. OutputManager calls `OutputGenerator.generate(snapshot)`
9. OutputManager updates DOM with new preview
10. App debounces; calls `storage.save('dj_library', model.djs)`

## Getting Started

### Prerequisites

- Node.js 16+ (npm or pnpm)
- A running Lineup Builder backend server (http://127.0.0.1:8000)

### Installation & Development

```bash
# 1. Install dependencies
cd web
npm install

# 2. Start dev server (auto-reload, API proxy to localhost:8000)
npm run dev
# Opens http://localhost:3000 in browser

# 3. (Optional) In another terminal, run the backend server
cd ../server
python -m uvicorn src.main:app --reload
```

### Build for Production

```bash
# Generate optimized dist/ bundle
npm run build

# Preview production build locally
npm run preview
```

### Environment Variables

Set `VITE_API_URL` to override the API base URL:

```bash
# Example: point to cloud API
VITE_API_URL=https://lineup-api.example.com npm run build
```

If not set, defaults to same origin (e.g., `https://example.com/api`).

## Development Guidelines

### Code Style
- **Vanilla JS** — no frameworks; use native DOM APIs
- **Modules** — ES6 imports/exports; one class per file (generally)
- **Naming** — CamelCase for classes, snake_case for internal methods (`_private`)
- **Comments** — JSDoc for public methods; inline comments for complex logic

### Testing
Currently no test suite. For future tests:
- Unit test `output-generator.js` (pure functions)
- Unit test `lineup-model.js` (mutable logic)
- Integration test managers against localStorage mock

### Performance Considerations
- **Debounce heavy operations** — use `setTimeout()` or `requestAnimationFrame()`  for resize/scroll
- **Lazy-load UI** — modals open on-demand, not at init
- **Batch DOM updates** — collect changes, then single update
- **Cache snapshot** — avoid re-computing event output unless model changed

### Debugging Tips
- **Open DevTools** — Inspector (DOM), Console (logs), Network (API calls)
- **Check localStorage** — `localStorage.getItem('lineup_events')`
- **Bus subscriptions** — add `console.log()` inside EventBus callbacks
- **API proxy** — vite dev server forwards `/api/*` to backend (check Network tab)

## Troubleshooting

### Issue: API calls fail with CORS error
**Solution:** Ensure backend is running on `http://127.0.0.1:8000` and Vite proxy is configured correctly (`vite.config.js`).

### Issue: Theme not persisting
**Solution:** Check `localStorage` in DevTools console. `ThemeManager` saves to `settings` key.

### Issue: Events not saving
**Solution:** Verify `StorageManager.load()` is called during `App.init()`. Check browser storage quota (unlikely to hit limit with lineups).

### Issue: DJ autocomplete not working
**Solution:** Ensure `RosterManager.refresh()` was called after loading events. DJ library may be empty.

### Issue: Drag-drop not working
**Solution:** Check `DragDropManager.init()` was called. Verify slot rows have correct DOM structure (drag handle must have `.drag-handle` class).
